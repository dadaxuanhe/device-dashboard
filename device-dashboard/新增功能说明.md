## 1. SSE 实时数据推送

### 概述
通过 Server-Sent Events (SSE) 技术，实现后端向前端浏览器的单向实时数据推送，替代传统轮询方式。支持自动重连。

### 涉及文件

| 文件 | 类型 | 说明 |
|------|------|------|
| `backend/sse.js` | 新增 | SSE 广播模块：客户端连接管理、心跳、事件广播 |
| `backend/server.js` | 修改 | 集成 SSE 端点 + 4 个数据模拟器 |
| `frontend/js/realtime.js` | 新增 | SSE 客户端：EventSource 封装、自动重连、事件分发 |

### 架构

```
┌─────────────────────┐     EventSource      ┌──────────────────────┐
│  前端页面            │ ←── SSE 流 ────     │  后端 Node.js       │
│                     │                      │                     │
│  index.html         │  事件类型:            │  GET /api/sse/events │
│  detail.html        │  • device-param-update   ← 模拟器① 6~9s    │
│                     │  • device-status-change  ← 模拟器② 25~35s   │
│  realtime.js        │  • alarm                 ← 增量检测 10s     │
│  (SSE 客户端)        │  • kpi-update            ← 统计计算 15s     │
└─────────────────────┘                      └──────────────────────┘
```

### 模拟器说明

| 模拟器 | 间隔 | 行为 | 推送事件 |
|--------|------|------|---------|
| ① 设备参数波动 | 6~9 秒 | 随机选 3~5 台设备，微调 1~3 个参数（±20%），限制在阈值范围内 | `device-param-update` |
| ② 状态变更 | 25~35 秒 | 随机选 1 台设备，切换为不同状态（加权随机） | `device-status-change` |
| ③ 新告警检测 | 10 秒 | 基于 lastAlarmId 增量查询新告警 | `alarm` |
| ④ KPI 刷新 | 15 秒 | 重新计算设备总数/运行/待机/故障/离线/产量/OEE/告警数 | `kpi-update` |

### 前端接入

```javascript
// 1. 启动连接
connectSSE();

// 2. 注册事件监听
onSSE('device-param-update', function(data) {
  // data.devices → [{ id, params: { temperature, current, ... } }]
  updateParamCards(data.devices);
});

onSSE('kpi-update', function(data) {
  // data → { total, running, idle, fault, offline, todayOutput, avgOee, alarmCount }
  updateKPICards(data);
});

// 3. 断开连接（页面卸载时自动）
disconnectSSE();
```

### 关键实现细节
- 心跳机制：每 15 秒发送 `:keepalive` 注释行，防止代理/浏览器超时
- 自动重连：断开后 10 秒自动重连
- 启动告警 ID 初始化：从数据库 `MAX(id)` 获取，避免推送历史告警
- 参数更新 SQL 动态拼接：只更新有变化的字段，防止未选中字段被写为 `null`

## 2. 温度趋势图实时更新

### 概述
设备详情页的温度趋势 ECharts 图表在加载历史数据后，通过 SSE 持续接收新数据点并实时追加到图表右侧。

### 涉及文件

| 文件 | 说明 |
|------|------|
| `frontend/pages/detail.html` | 修改，新增 `_chartData` 缓存和 SSE 图表更新逻辑 |

### 实现

```
SSE device-param-update 事件
    │
    ├─→ 更新参数卡片（已有）
    │
    └─→ 如果 temperature 字段存在
         ├─→ 格式化当前时间 HH:mm:ss 作为 X 轴标签
         ├─→ 追加 { time, value } 到 _chartData 数组
         ├─→ 保持最多 60 个点，超出时移除最早数据
         └─→ chartInstance.setOption() 增量刷新图表
```

### 数据流
1. 页面加载 → `loadDetail()` → `getEquipmentTemperature(id, { range:'7d' })` → `renderTrendChart(data)` → `_chartData = data`
2. SSE 推送 → 温度变化 → `_chartData.push({ time: '14:30:25', value: 36.8 })` → `chartInstance.setOption({ xAxis, series })`

## 3. 设备编号自动生成

### 概述
添加设备弹窗打开时，自动从后端获取下一个可用的设备编号并填入表单。

### 涉及文件

| 文件 | 说明 |
|------|------|
| `backend/server.js` | 新增 `GET /api/equipment/next-no` 端点 |
| `frontend/js/api.js` | 新增 `getNextEquipmentNo()` 函数 |
| `frontend/pages/detail.html` | 修改 `openAddDevice()` 自动填充 |
| `frontend/js/dashboard.js` | 修改 `openAddDevice()` 自动填充 |

### API

```
GET /api/equipment/next-no
→ { code: 0, data: { nextNo: "EQ-014" } }
```

编号规则：`EQ-` + 3 位序号（递增），基于数据库中最大 EQ 编号 +1。

## 4. 关注设备角色权限控制

### 概述
"关注设备"功能仅对普通员工（viewer）角色可见可用，其他角色隐藏按钮并禁止 API 调用。

### 涉及文件

| 文件 | 说明 |
|------|------|
| `frontend/index.html` | CSS 修改：`.fav-toggle` → `body.is-viewer .fav-toggle` |
| `frontend/pages/detail.html` | CSS 修改：`.fav-btn-detail` → `body.is-viewer .fav-btn-detail` |
| `backend/server.js` | API 路由添加 `requireRole('viewer')` 中间件 |

### 权限矩阵

| 角色 | 前端按钮 | 后端 API |
|------|---------|---------|
| 普通员工 (viewer) | ✅ 可见 | ✅ 200 OK |
| 看板管理员 | ❌ 隐藏 | ❌ 403 Forbidden |
| 车间主管 | ❌ 隐藏 | ❌ 403 Forbidden |
| 设备维修员 | ❌ 隐藏 | ❌ 403 Forbidden |

## 5. 其他修复

### 5.1 删除设备误报修复

**问题**：API 删除成功返回 `data: null`，但前端用 `if (r && r.success !== false)` 判断，
`null && ...` 为 falsy，导致进入 else 分支报"删除失败"。

**修复**：简化判断逻辑，直接 `await deleteEquipment(id)`，由 `request()` 统一处理错误。

### 5.2 添加设备 JSON.stringify 缺失

**问题**：`addEquipment(data)` 直接传递 JS 对象作为 `body`，
`fetch` 将其转为 `[object Object]` 字符串，后端解析失败返回 500。

**修复**：`body: JSON.stringify(data)`
