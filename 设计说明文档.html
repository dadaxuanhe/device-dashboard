智能工厂设备监控看板系统 · 完整设计文档

一 项目概述

本系统是一个面向制造车间的设备监控看板，提供设备实时状态监控、生产数据可视化、告警管理和设备详情查询等功能。采用 B/S 架构，通过浏览器即可访问，无需安装客户端。后端基于 Node.js + Express 提供 RESTful API，前端使用 原生 HTML + CSS + JavaScript（ES6+） 实现，图表基于 ECharts 5.x，数据库使用 SQLite3 嵌入式存储。

三 设计思路

整体架构

前端（原生 HTML+CSS+JS + ECharts）→ HTTP → 后端（Node.js + Express）→ SQLite3

采用单服务托管模式：Express 通过 express.static 统一托管前端静态文件，所有 API 统一返回格式 { code, data, message }。前端不依赖构建工具，直接运行。

响应式策略

断点侧边栏网格导航
PC ≥1024px展开 240px4 列侧边栏
平板 768–1023px折叠抽屉2 列汉堡菜单
手机 ≤767px隐藏单列底部 Tab 栏

UI 风格

参考 CoreUI Admin 模板：侧边栏 #1a1e2e 深色背景，激活项紫色 #6C3FF5 左边框，卡片 8px 圆角 + 微阴影，Font Awesome 6 图标库。暗色/亮色双主题通过 CSS 变量实现切换。

技术选型理由

  • 原生三件套：零构建步骤，直接运行，适合教学演示
  • ECharts 5.x：功能丰富，深色/浅色自适应，CDN 加载
  • SQLite3：零配置嵌入式数据库，文件级存储，适合中小型应用
  • Express：最流行的 Node.js 框架，中间件生态完善

七 功能实现说明

1. 设备总览模块（index.html）

  • KPI 卡片：8 张卡片（设备总数 / 运行中 / 待机 / 故障 / 离线 / 今日产量 / 平均稼动率 / 未处理告警），带趋势标签（+5.2% / -2.0%）
  • 搜索筛选：按设备名称/编号实时搜索（300ms 防抖），支持清除按钮和搜索结果条
  • 设备卡片网格：4 列（PC）/ 2 列（平板）/ 1 列（手机），hover 紫色边框
  • 点击卡片跳转详情页（URL 带 id 参数）
  • 视图切换：卡片 ↔ 列表（localStorage 持久化）

2. 数据可视化模块（ECharts）

  • 产量折线图：计划产量 / 实际产量 / 良品数 3 条曲线
  • OEE 环形图：双环设计 — 外层整体 OEE + 内层各设备分布
  • 温度曲线图：多设备多色显示，含上下阈值标注
  • 时间范围切换：今日 / 近 7 天 / 近 30 天，三个图表联动刷新

3. 告警管理模块（alarms.html）

  • 告警统计摘要：紧急 / 重要 / 一般 数量 + 总计
  • 告警列表：级别 / 状态 / 设备 三栏筛选 + 分页
  • 确认/清除：状态校验 —— 仅 active 可确认，仅 confirmed 可清除
  • 告警滚动条：首页顶部滚动显示活跃告警，悬停暂停
  • CSV 导出：带 BOM 的中文编码，从当前表格数据导出
  • 紧急弹窗：新 critical 告警弹出，localStorage 去重

4. 设备详情模块（detail.html）

  • 设备信息头部：名称 / 编号 / 型号 / 制造商 / 位置 / 安装日期
  • 4 个实时参数卡片：温度 / 电流 / 电压 / 压力，含阈值指示条（正常 / 接近阈值 / 超阈值）
  • 温度趋势图（ECharts 面积图）+ 维修历史表格

5. 人员管理模块（personnel.html）

  • 值班人员卡片网格：8 人，含职位徽章（管理员/工程师/操作员）
  • 操作记录表格：按人员筛选
  • 绩效柱状图：ECharts 产量排名

6. 系统设置模块（settings.html）

  • 主题设置：暗色/亮色 Radio，即时生效
  • 数据刷新间隔：5s / 10s / 30s / 60s 可选
  • 默认时间范围：今日 / 7天 / 30天
  • 默认设备视图：卡片 / 列表
  • 告警通知：弹窗通知 + 声音提醒 Toggle
  • 用户管理：只读表格（调用 GET /api/users）
  • 保存/恢复默认按钮 + Toast 动画提示

7. 用户认证模块（login.html）

  • 登录/注册同页 Tab 切换
  • 登录守卫：未登录自动跳转到 login.html

八 遇到的问题与解决方案

🔴 问题 1：SQLite 异步建表与数据初始化竞态
解决方案：通过 Promise + db.serialize() 确保建表完成后再插入数据，导出 waitForDb() 返回 Promise 确保表结构就绪后执行后续操作。
🔴 问题 2：前端 ES Module 与全局 Script 的兼容
解决方案：每个模块同时支持 export 和 window.xxx 全局导出，底部添加 window.xxx = xxx 兼容传统 script 标签。共导出 71 个全局函数。
🔴 问题 3：SQLite 外键约束导致确认告警操作失败
解决方案：确认告警时不更新 confirmed_by（原为 INTEGER FK 引用 personnel 表），仅更新 confirmed_at 时间戳，handler 信息仅在响应中返回，避免外键冲突。
🔴 问题 4：侧边栏重构导致样式污染
解决方案：统一删除 index.html 中的内联 <style>（约 450 行），全部迁移到外部 CSS 文件。统一所有页面的侧边栏 HTML 结构和 class 命名，消除重复标签。
🔴 问题 5：亮色主题下文字对比度不足
解决方案：在 [data-theme="light"] 中加深 --text-secondary 和 --text-muted 变量，将设备名称、KPI 标签等文字颜色改为 var(--text-primary)，确保白底上的可读性。
🔴 问题 6：常量声明导致的服务器崩溃
解决方案：后端 const summarySql 拼接 SQL 时因 const 限制抛出 TypeError，改为 let 修复。同时修复告警级别筛选映射（major→warning, minor→info）使前端筛选生效。
